# Linear Comment Style

How a comment on a Linear issue or project reads. Comments record what changed from the recorded plan — decisions, rejected approaches, discovered blockers, corrected assumptions — never a summary or status narrative.

## Style

- **An owned comment is yours to fix** per `agent-owned` — edit it, or delete it while it has no replies, without asking.
- **Lead with what changed** — "Switched from X to Y because Z."
- **No filler** — no greetings, no restating the record, no "just wanted to note".
- **Facts and decisions only.**
- **Length matches the finding** — a single deviation is one sentence; a research session with several findings gets bullets and an appendix.

## Appendix

When the session produced research or reasoning worth preserving:

```markdown
## Findings

- [Bullet list of key deviations and decisions]

## Appendix

[Research trail, options considered, reasoning, links to code or docs]
```

Use the appendix when the comment would otherwise lose context future readers need to understand why.
